# AETP Threat Model

## Protected secrets

The protected difference between paired worlds may be evidence rise shape, threshold margin,
private readiness time, hidden identity signature, evidence duration, private context trajectory,
confidence, or cross-service physiological timing correlation.

## Adversaries

- passive network observer using timing, count, size, ciphertext statistics, aliases, and drops
- timing-only observer using timestamps, silence, cadence, count, and public drop pattern
- authorized-but-curious service seeing its decoded cover/action sequence and public policy
- colluding services combining action slots, lag, simultaneity, and pairwise traces
- longitudinal observer combining 1, 4, 16, or 64 buckets
- auxiliary-information attacker knowing design, policy family, pair family, and public context

Attackers receive the allowed action semantics. Their task is to distinguish which private member
of an action-equivalent pair generated the trace.

## Trusted computing base

The admission boundary, AETS process, AEAD implementation, random tape generation, and key store
are trusted. Public network loss is adversarially observable but fixed by the common public tape
for the counterfactual game.

## Non-goals

- compromised endpoint or operating-system access to High Side memory
- malicious sensor firmware or fabricated raw measurements
- baseline poisoning or K1 statistical validity
- replay, forgery, revocation, or token theft
- visible-action inference by a bystander
- hiding action/no-action or other differences in allowed semantics
- production BLE, radio firmware, traffic overhead, and user study conclusions

## Falsification

AETS fails if any efficient held-out attacker distinguishes paired worlds beyond the declared
bound, if any coupled trace differs under the same public tapes, if utility or deadlines fail, or
if private state reaches the shaper dependency graph, serialized frames, errors, or audit.
