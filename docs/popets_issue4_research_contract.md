# PoPETs 2027 Issue 4: 受信者結託下の回復トレース

## 一文での主張と解禁条件

**目標主張:** 許可済みの行動が同じでも、正規の受信者が受領・再送・再接続の履歴を突き合わせると非公開の準備状態が漏れ得る。AETPはこの余剰漏洩を定義し、QuotientForgeは明示した障害境界内で、期限と動作を保つ正規化機構を検証可能な形で合成する。

これは投稿前に満たすべき主張であり、現時点の実測結果の要約ではない。
後半を本文で断定するには、実際に合成した機械、独立チェッカー、実装への対応と
期限達成を同じ入力・実験IDで束縛する。今回の小さなスケジューラは手で定義した
構成則であり、QuotientForgeの合成・証明連携の代わりにはならない。

## 1. 観測ゲーム

公開文脈を c、許可される動作契約を a とする。挑戦用の私的履歴 h0 と h1 は、
両方が同じ a を満たし、同じ公開文脈・障害契約で適格でなければならない。
a は行動の種類・引数・許可された受信者・公開の時間窓・完了と回復の義務を
定める。実際の準備時刻や診断情報を a に加えて問題を定義から消さない。

挑戦者は一様な秘密ビット b を選び、機構を hb 上で実行する。観測者は許可された
受信者集合 C の時系列ログを結合したビュー V_C を受け取り、b を推定する。
同じ公開入力の列を使う。現段階は固定の公開入力列に対する結果のみであり、
適応的な障害・受信者による状態依存入力への一般化は別の証明義務とする。

- 分布的な完全版: 各適格ペア、各公開入力列、各指定結託に対して両ビューの分布が等しい。
- TV近似版: 分布の全変動距離が宣言した上限 delta 以下。等事前確率のゲームで最良の
  正答率は (1 + delta) / 2 以下。成功確率から1/2を引く流儀ならadvantageはdelta / 2以下。
- 点ごとの一致: 指定した共有乱数でビューが一致する十分条件。固定した乱数で生じる差は、
  乱数を隠した観測者の周辺分布の差と同じではない。
- 実用性: 許可済みの行動と回復義務は期限までに一度だけ実行し、許可外の動作は出さない。
  試行を抑止してプライバシー指標だけ改善する方式は合格しない。

[Pufferfish](https://doi.org/10.1145/2514689)の秘密対・分布族にこの実験の条件を
特定できる場合、完全一致はその指定分布に対するepsilon=0の事例として扱える。
有用性は同時に課す仕様であって、Pufferfishがトレースを扱えないという主張ではない。
TV境界を一般の乗法的PufferfishやDP保証と置き換えない。

## 2. 二つの観測範囲

| 実験 | 保護する観測 | 守らないもの |
|---|---|---|
| 受信サービスとその結託 | 同じ許可済み行動に対する受信者ログの時刻・順序・回復メタデータ | 行動そのものの有無、範囲外ログ、盗聴者への通信形状 |
| ネットワーク形状の追加保護 | 同じ公開サービス窓・障害列における、行動あり・なし間のフレーム時刻、長さ、公開サービス | 暗号の中身の保証、パケット以外の副経路、公開窓や障害列の秘匿 |

二つ目の「あり・なし」は違う動作契約をネットワーク観測者に限って比較する、
強い別目標である。同一動作クラス内でのAETPを定義するだけなら、
あらゆる設定でカバートラフィックが必要だとは結論しない。

## 3. 実行済みの根拠

- 既存Rust AETPの合成64ペアでは、受信時刻のTVは0。準備次第で送るローカルの
  Pacer風・NetShaper風はTV 1だが、同じ公開開始時刻まで待つPacer風もTV 0。
  公開待ちに対する固有の優位は示していない。
- 欠陥を注入した有限モデルでは、スロット3の回復後受領通知に関する反例をRustと
  Pythonが一致して検出した。固定乱数ごとの比較と、乱数を周辺化したTVを別々に記載する。
  既存の手書き実装に同じ欠陥を発見したわけではない。
- 新しい公開窓の構成則では、2サービス、各3スロット、各サービスで最大1欠落の
  共有公開テープ16本と4つの行動集合を全列挙した。1サービスにつき1行動・共用帯域や
  多重化なし。フレームはモデル上256 B。予算を超えるテープは対象外であり、成功に数えない。

| 合成モデルの方式 | 受信結託ビューの差 / 64ペア | アイドルと異なる通信形状 / 64条件 | 期限内 | 平均モデルバイト |
|---|---:|---:|---:|---:|
| 受信者のみ | 0 | 48 | 64/64 | 256 |
| スロットを合わせるネットワーク用方式 | 0 | 0 | 64/64 | 512 |
| 窓内の定レート | 0 | 0 | 64/64 | 1,152 |
| 期限で初めて試行 | 0 | 39 | 48/64 | 192 |

比較対象が異なる前回の実装由来ランでは、AETPは241,664 B/世界、開発設定の
Pacer風は34,928 B/世界だった（約6.9倍）。上の合成表で上書き・相殺しない。
上の表ではACK、送信後損失、再送、再接続やパケットの共有帯域競合をモデル化して
いない。欠落は送信前の公開 availability であり、フレームの発行を即完了と仮定した。

### 限定モデルでの下限

行動ありの各サービスは期限内に最低1フレームが必要とする。そのサービスが
空である世界とネットワーク形状を同じにするなら、空の世界でも同じ公開テープでは
最低1フレームが必要になる。最初の利用可能スロットに1フレームを出す構成は、
この独立レーン上の下限に達する。ただし共有帯域、確率的な秘匿、観測者の追加情報、
実網での再送を含む最適性の主張ではない。

### 公開データの確認的評価（未実施）

[WESAD](https://archive.ics.uci.edu/dataset/465/wesad)のストレス条件は実験ラベルであり、
健康状態の診断ではない。[PPG-DaLiA](https://archive.ics.uci.edu/dataset/495/ppg+dalia)
では活動・体動との関係を別に扱い、ストレスの真値にしない。準備時刻とは事前定義した
ルールの初回適格スロットであり、本人の地の状態変化時刻ではない。

ラベルを見ずに窓化と除外を固定し、学習・調整・評価で参加者を分離する。
収録内の区間を独立セッションに数えない。比較は公開行動だけの参照と、クリアした
機微性評価に限る。両条件が存在する行動クラスの割合、参加者ごとのサポート有無、
脱落分母と参加者単位の不確実性を報告する。原波形・行データ・参加者別の時刻は公開しない。
適格データが足りなければ `inconclusive` とし、追加の人対象研究は組織の倫理手続きに従う。
現時点では実データを取り込まず、独立性・機微性の結果も主張しない。

## 5. 形式保証、関連研究、原稿

明示ホライズンを仮定し、同じ公開入力を受ける動作等価な状態対の到達積状態に
bad stateが無ければ、指定観測者の一致、許可外動作の不在、一度だけの期限内完了を導く。
