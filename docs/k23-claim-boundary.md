# K23: Sharpen the claim without enlarging the guarantee

The research candidate is not a new matching theorem or a new online minimax
argument. It is a recipe for separating four outcomes in one release contract:
receipt equality within an authorized action class, feasible offline capacity,
causal classification of what can be guaranteed, and an independently checked
reason when a promise fails.

| Result | What it establishes | What it does not establish |
| --- | --- | --- |
| A complete assignment | A fixed public tape can meet the stated deadlines | A causal implementation under unknown future availability |
| A Hall deficit | No offline schedule for this input can meet all deadlines | That any real deployment uses this model |
| Two incompatible first choices | No deterministic first send works for both modeled futures | A multi-slot synthesis lower bound or a privacy leak |
| Equal emitted counts | Same modeled frame-count projection | Same decoded receipt trace, wire bytes, or physical timing |
| Independently equal receipt logs | Equality on the selected admitted synthetic contexts | Empirical suppression of sensitive attributes |

Next differentiator: a compiler accepting an explicitly declared public
uncertainty class, producing a causal strategy or a compact counterexample,
and separately certifying receipt equality and frame budgets. Compare with
strong causal policies under exactly the same information and promises before
claiming any improvement, and with verified offline allocation only as a
ceiling. Production protocol recovery, empirical privacy, and historical
priority remain unverified.
