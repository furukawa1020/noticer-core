# K22: 回復機構の主張と証拠の対応

| 主張の候補 | 根拠 | 許されない読み替え |
|---|---|---|
| 同じ許可行動で受信時刻が一致する | Rust AETPの合成64ペア、および同じ公開開始を課した対照も一致 | 単純な公開待ちに対するプライバシー優位 |
| 結託でだけ区別できる分布はあり得る | 故障を与えた有限の合成例で、乱数を周辺化した結合分布のTVが1 | 実装や本番製品に発見した脆弱性 |
| 指定モデルではプライバシーと期限を両立できる | 実際に合成した表、RustとPythonの独立判定、ローカル受信ログの照合 | プロトコル全体のセキュリティ証明、すべての障害への保証 |
| 明示した範囲では合成機構が小さくなる | 緩い期限のケースでは機械状態が1対2、通信量同値、遅延では手書き優位 | コストのどの軸でも合成が優越する |
| 期限まで待つだけで十分か | 公開窓を塞ぐ合成条件では時刻差はないが期限違反 | 手書き対照が必ず漏洩する |
| 実ネットワーク上でも同じ性質が残る | 未取得 | 主張しない |
| 参加者の機微な状態と準備時刻に関連がある | 未取得 | 主張しない |

論文中では証拠を同じ実験ID・版・観測範囲の中で対応させる。
ランタイムの合成受信ログを実ネットワークや実生体の実測に含めない。
